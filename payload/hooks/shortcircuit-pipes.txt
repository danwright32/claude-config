# How many short circuiting pipelines each file still has, one "count path" per line
# (claude-config#132).
#
# `producer | grep -q needle` under `set -o pipefail` can report a failure that never happened:
# grep -q leaves on its FIRST match, the producer is killed by SIGPIPE, and the pipeline's status
# becomes that death (L183). `head` is the same shape.
#
# It only bites when the reader leaves while the writer still has data, so it depends on how big
# the text is and where in it the match falls. That makes it a SIZE THRESHOLD nobody watches: two
# of these were correct for months and broke the week their input grew. The sync suite's citation
# check started failing on Linux when the file it read gained one line per suite, and the lessons
# advisory went silent on any push adding more than a pipe buffer of lines, which is when it has
# most to say.
#
# This is a ratchet, not an inventory. test-pipefail-shortcircuit.sh derives the real counts and
# fails if any file's count GROWS, so a new one is caught on the day it lands. It also fails when a
# count here is HIGHER than the file's, which forces the number down as sites are converted rather
# than letting it sit as a permanent allowance (L182).
#
# To convert one: read the producer into a variable and match with `case "$var" in *needle*)`, or
# write it to a file and let grep read the file. Both remove the pipe entirely.
#
# The ones left are overwhelmingly `printf '%s' "$var" | grep -q` inside tests, where the text is a
# fixture the test itself built. That is a real distinction and not a comfortable one: it holds
# only while the fixture stays small.
