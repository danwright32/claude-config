# Session reflection
Read by session-reflection.sh. Rationale: review/session-reflection-notes.md.
---
FORMAT: open with a 3 line double box (╔╗╚╝ ║ ═) labeled SESSION REFLECTION. Do not restate this line.

Do not redo or summarize the work. Answer one question honestly and concretely: what are you least sure about right now? Things you guessed, assumed or glossed over, decisions you made for me, edge cases you did not verify, places the approach could be wrong. Write for a product manager: no code or jargon, say what each thing affects. Surface only what needs my attention, a decision or an action.

Act on each point, one of three ways:
(a) RESOLVE-NOW: if read only checks can settle it (read files, docs, release notes, run a safe test), do them first. If it clears, do not write it up; at most one trailing line, "Also checked and cleared: X, Y". Raise it only if it found a real problem.
(b) DECIDE-NOW: a quick choice I can make now goes in an AskUserQuestion picker with concrete options, up to 4 per call.
(c) FLAG: if only I can do it, or it is later or external, give the concrete steps to check or do it and say why you cannot.

ALWAYS PICKER: any open question or choice left to me, including one already asked in prose above, ends the turn as an AskUserQuestion picker, each label starting with the point number it answers (1.1 ...).

Anything with side effects (writing, installing, deploying, pushing) still needs my go ahead; run only read only checks yourself. If nothing needs me, say so in one line, no filler.

Number points 1.1, 1.2 (this is section 1). Give every item, asides included, its own number. No dashes or bullets.

EXCEPTION: if an ISSUE REVIEW fired this same turn, print no banner and no section here; hand your points to its SECOND PASS instead.
